# Реализация требований

Основание: ТЗ от 15 октября 2026, версия 1.0. Статус 0.2.1 означает рабочее ядро и часть жизненного цикла, а не полный релиз всех этапов 0–8.

| Область ТЗ | Состояние | Проверка и ограничения |
| --- | --- | --- |
| Telegram initData и API-права | Реализовано | Подпись, свежесть, tampering, третий аккаунт, выход и возврат проверены тестами |
| Одноразовое приглашение | Реализовано | Два конкурирующих присоединения дают одного победителя; открытие страницы само по себе ссылку не расходует |
| Состав пары | Реализовано | Закреплённые ID не меняются при выходе; заменить участника API не позволяет |
| Календарные виды и темы | Реализовано | Браузерная проверка 390 и 1280 px, 42 ячейки месяца, 7 дат недели, почасовой день, RU/EN и обе темы |
| CRUD, категории, поиск и фильтры | Реализовано | База на диске, проверки пересечений без запрета, optimistic concurrency через revision |
| Повторения и исключения | Реализовано в ядре | COUNT, RRULE, второй вторник, DST, экземпляр/последующие/серия, корзина исключений проверены; сложные комбинации требуют более широкой регрессии |
| Часовые пояса и весь день | Реализовано | Фиксированные даты, IANA зоны, проверка пропущенного и повторяющегося часа |
| Персональные напоминания | Реализовано | До трёх, настройки каждого отдельно, полный пересчёт при переносе, нет догоняющей отправки |
| Внутренние Telegram-уведомления | Реализовано | Только второму; название/описание отдельно не уведомляют; бот требует Start; ошибки записываются |
| Настоящая доставка Telegram | Нужна проверка размещённого сервиса | Здесь использовался подставной транспорт; BotFather-токен и публичный URL не предоставлены |
| RU/EN интерфейс и ручные версии | Реализовано | Оригинал сохраняется, ручной перевод отмечается устаревшим при изменении оригинала |
| Автоматический перевод и «Перевести заново» | Реализован подключаемый модуль | События/категории, очередь, LibreTranslate, защита ручных версий и конкурентных изменений; нужен настроенный URL и живая проверка |
| Google OAuth, ручной выбор и синхронизация | Пилотный read-only адаптер | PKCE, scopes только чтения, pagination, sync token/410, фильтр выбранных ID и vault тестируются отдельно. Аккаунты, OAuth callback/state lifecycle, два этапа выбора, связи и очередь ещё не соединены с Mini App |
| Apple/iCloud | Пилотный CalDAV read-only адаптер | Discovery и REPORT, HTTPS host allowlist, запрет перенаправления credentials и XML entities; на реальном аккаунте ещё не проверен |
| Политика readonly и конфликты по полям | Доменный модуль и тесты | `sync_policy.py` проверяет запрет записи, владельца, независимое слияние и групповое время; с провайдерами ещё не соединён |
| «Удалить везде» и конфликты двух владельцев | Не реализовано в продукте | Есть правила ожидания/отказа как доменные функции; внешних удалений и экранов согласования пока нет |
| Корзина 30 дней | Реализовано | Обычные события, серии, сегменты и отдельные экземпляры; очищенный экземпляр не появляется снова в серии |
| ICS | Реализовано | Парсинг полученного ICS, Unicode, VTIMEZONE, RRULE и RECURRENCE-ID проверены локально; импорт в реальных Apple/Google требует теста |
| Подписанный ZIP активного календаря | Реализовано | Проверка подписи и целостности, запрет другого календаря, diff и ручной выбор полей/отсутствующих событий |
| Восстановление overrides активного ZIP | Реализовано | Различия по полям исключений, удаление поздних overrides, согласованное состояние удаления, выбор своих настроек, защита устаревшего/чужого/повторного предпросмотра |
| Полное удаление и 30-дневный экран | Реализовано | Два согласия, закрытый доступ, пауза, отмена, очистка основного календаря |
| ZIP после полного удаления | Реализовано | Подлинность/ID исходной пары, два согласия, без внешних связей, напоминания каждого выключены |
| Production эксплуатация | Подготовлено, не завершено | Созданы отдельные Railway project/service, EU volume и HTTPS domain; добавлены закрытый setup mode и автоматическая регистрация webhook. Нужны BOT_TOKEN/BOT_USERNAME, мониторинг и реальный приёмочный прогон |
| Нагрузка и GDPR | Требует отдельной проверки | Не является юридическим заключением или завершённым security audit |

## Следующие задачи

1. Репозиторий создан пользователем и заполнен: https://github.com/wpclwe-ops/our-calendar. Проверки bootstrap-коммита прошли в GitHub Actions.
2. Настроить BotFather/HTTPS/volume, проверить двумя реальными Telegram-аккаунтами все сценарии P0.
3. Расширять UI-регрессию форм, ZIP и ручных конфликтов; сравнение исключений и персональных настроек реализовано.
4. Настроить выбранный LibreTranslate и проверить настоящий перевод в размещённом сервисе; программная очередь реализована.
5. Реализовать Google read-only OAuth, двухэтапный ручной импорт и incremental sync. Секреты шифровать; не выдавать чужие невыбранные записи.
6. Реализовать внешние связи и общий конфликтный workflow, затем Google two-way. Абсолютный серверный запрет записи в import-only обязателен.
7. Провести пилот Apple/iCloud и реализовать только реально подтверждённые операции.
8. Реализовать внешние удаления/частичные сбои, revalidation после паузы/ZIP, watch renewal и полный набор интеграционных тестов.
9. Провести проверку безопасности, восстановления при аварии и эксплуатационный релиз.

Все эти пункты сохраняют исходный объём продукта. Не реализованные возможности не заменены декоративными работающими на вид кнопками.

## Исправление 16.10.2026: уведомление о начале

По сообщению пользователя добавлено отдельное уведомление в момент начала события (дополнение к §7.1 исходного ТЗ). Включено по умолчанию, в том числе для прежних аккаунтов и существующих событий. Персональный переключатель `notify_at_start` применяется ко всем событиям и сохраняется в ZIP; общий `reminders_enabled` имеет приоритет. Три предварительных интервала остаются независимыми. Для событий «Весь день» используется полночь получателя. Истёкшие точки не догоняются, очередь не дублируется. Отправка идёт в очередном цикле фонового обработчика, не как точный системный будильник. Реальное получение на пользовательском устройстве требует подтверждения пользователя.

## Интерфейс 16.10.2026: макеты Claude

Визуальная основа: https://claude.ai/artifact/3XCHPg498S8eeex1GTFhzk#page-dcb81aee8d83 (Our Calendar — iPhone mockups, 12 artboards). Перенесены палитры light/dark, системная типографика, компактная верхняя панель, сегменты Месяц/Неделя/День, календарная сетка во весь доступный экран, пастельные полоски событий и FAB, недельная лента/список, почасовой день, сгруппированные формы, карточка события, поиск, список категорий и редактор в нижней панели, группы персональных/общих настроек. Сетка месяца имеет 4/5/6 недель в зависимости от месяца. На больших экранах компоновка адаптируется.

Сохранены реальная серверная авторизация, API, права пары и напоминания о начале. Прототипные подключённые Google/iCloud, синхронизация, автоматический перевод, история авторов и «Удалить везде» не подменяются вымышленными статусами. Google/iCloud обозначены как ещё недоступные. Демо-данные находятся только в изолированном статическом `web/design-preview.html`: этот документ перехватывает fetch в собственном окне, не создаёт серверных сессий и не обращается к календарным API. Основной вход через Telegram остаётся защищённым. Предпросмотр использует тот же app.js/CSS; ?phone=1 показывает 390×844, ?lang=en и ?theme=dark переключают демонстрационные язык и тему.

## Дополнительный вид дня: список

По референсу пользователя добавлен персональный `day_layout`: timeline (по умолчанию для прежних/новых пользователей) или list. Выбор находится на вкладке День и хранится на сервере отдельно от month/week/day; включён в подписанные ZIP и выборочное восстановление собственных настроек. Список показывает события выбранной даты с полным названием, локальным временем, цветом категории, принадлежностью, кнопкой выполнения/возврата и удалением через существующее подтверждение/выбор области серии. Выполнение повторяющегося события меняет только один экземпляр; удаление использует существующую корзину. Новые функции из стороннего референса не добавлены.
