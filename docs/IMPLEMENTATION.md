# Реализация требований

Основание: ТЗ от 15 октября 2026, версия 1.0. Статус 0.1.0 означает рабочее ядро и часть жизненного цикла, а не полный релиз всех этапов 0–8.

| Область ТЗ | Состояние | Проверка и ограничения |
| --- | --- | --- |
| Telegram initData и API-права | Реализовано | Подпись, свежесть, tampering, третий аккаунт, выход и возврат проверены тестами |
| Одноразовое приглашение | Реализовано | Два конкурирующих присоединения дают одного победителя; открытие страницы само по себе ссылку не расходует |
| Состав пары | Реализовано | Закреплённые ID не меняются при выходе; заменить участника API не позволяет |
| Календарные виды и темы | Реализовано | Браузерная проверка 390 и 1280 px, 42 ячейки месяца, 7 дат недели, почасовой день, RU/EN и обе темы |
| CRUD, категории, поиск и фильтры | Реализовано | База на диске, проверки пересечений без запрета, optimistic concurrency через revision |
| Повторения и исключения | Реализовано в ядре | COUNT, RRULE, второй вторник, DST, экземпляр/последующие/серия, корзина исключений проверены; сложные комбинации требуют более широкой регрессии |
| Часовые пояса и весь день | Реализовано | Фиксированные даты, IANA зоны, проверка пропущенного и повторяющегося часа |
| Персональные напоминания | Реализовано | До трёх, настройки каждого отдельно, полный пересчёт при переносе, нет догоняющей отправки |
| Внутренние Telegram-уведомления | Реализовано | Только второму; название/описание отдельно не уведомляют; бот требует Start; ошибки записываются |
| Настоящая доставка Telegram | Нужна проверка размещённого сервиса | Здесь использовался подставной транспорт; BotFather-токен и публичный URL не предоставлены |
| RU/EN интерфейс и ручные версии | Реализовано | Оригинал сохраняется, ручной перевод отмечается устаревшим при изменении оригинала |
| Автоматический перевод и «Перевести заново» | Не реализовано | Нужен выбранный сервис перевода, конфигурация и проверка сохранности ручных версий |
| Google OAuth, ручной выбор и синхронизация | Не реализовано | Не выданы client credentials; нужны adapter, encrypted credentials, таблицы связей, очередь sync, reconnect и реальные пилотные тесты |
| Apple/iCloud | Не реализовано | Сначала доказать подход авторизации/CalDAV на реальном аккаунте, как требует ТЗ |
| Политика readonly и конфликты по полям | Доменный модуль и тесты | `sync_policy.py` проверяет запрет записи, владельца, независимое слияние и групповое время; с провайдерами ещё не соединён |
| «Удалить везде» и конфликты двух владельцев | Не реализовано в продукте | Есть правила ожидания/отказа как доменные функции; внешних удалений и экранов согласования пока нет |
| Корзина 30 дней | Реализовано | Обычные события, серии, сегменты и отдельные экземпляры; очищенный экземпляр не появляется снова в серии |
| ICS | Реализовано | Парсинг полученного ICS, Unicode, VTIMEZONE, RRULE и RECURRENCE-ID проверены локально; импорт в реальных Apple/Google требует теста |
| Подписанный ZIP активного календаря | Реализовано | Проверка подписи и целостности, запрет другого календаря, diff и ручной выбор полей/отсутствующих событий |
| Восстановление overrides активного ZIP | Требует доработки | Восстанавливаются с отсутствующей серией. Сравнение и выбор отдельных отличий исключений существующей серии пока отсутствуют |
| Полное удаление и 30-дневный экран | Реализовано | Два согласия, закрытый доступ, пауза, отмена, очистка основного календаря |
| ZIP после полного удаления | Реализовано | Подлинность/ID исходной пары, два согласия, без внешних связей, напоминания каждого выключены |
| Production эксплуатация | Подготовлено, не завершено | Docker, Railway, persistent volume, CI, SQLite backup. Нужны TLS deployment, мониторинг и реальный приёмочный прогон |
| Нагрузка и GDPR | Требует отдельной проверки | Не является юридическим заключением или завершённым security audit |

## Следующие задачи

1. Создать приватный GitHub-репозиторий, загрузить этот проект и убедиться, что Actions проходят в чистом окружении.
2. Настроить BotFather/HTTPS/volume, проверить двумя реальными Telegram-аккаунтами все сценарии P0.
3. Доделать выборочное сравнение исключений и персональных настроек в активном ZIP; расширить UI-тесты форм и восстановления.
4. Подключить сервис автоматического перевода с независимыми ручными RU/EN версиями.
5. Реализовать Google read-only OAuth, двухэтапный ручной импорт и incremental sync. Секреты шифровать; не выдавать чужие невыбранные записи.
6. Реализовать внешние связи и общий конфликтный workflow, затем Google two-way. Абсолютный серверный запрет записи в import-only обязателен.
7. Провести пилот Apple/iCloud и реализовать только реально подтверждённые операции.
8. Реализовать внешние удаления/частичные сбои, revalidation после паузы/ZIP, watch renewal и полный набор интеграционных тестов.
9. Провести проверку безопасности, восстановления при аварии и эксплуатационный релиз.

Все эти пункты сохраняют исходный объём продукта. Не реализованные возможности не заменены декоративными работающими на вид кнопками.
