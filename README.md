# Our Calendar

Приватный общий календарь для неизменяемой пары Telegram-аккаунтов. Telegram Mini App, бот, сервер и постоянное хранилище находятся в одном проекте.

**Версия 0.1.0 — рабочее ядро, ещё не завершённая реализация всего ТЗ.** Код запускается локально; для реального использования нужно разместить сервер, настроить Telegram-бота и пройти проверку двумя настоящими аккаунтами. Google/iCloud и автоматический перевод пока не подключены. Полная таблица готовности: [docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md).

## Что уже реализовано

- Серверная проверка подписи Telegram `initData`, срока действия и полномочий на каждое действие.
- Создание календаря, одноразовая отзываемая ссылка, атомарное присоединение первого второго участника; запрет третьего и замены пары.
- Выход с сохранением событий и возвращение только того же Telegram-аккаунта.
- Создание и редактирование событий, RU/EN версии текста, категории/цвета, принадлежность, статусы, место, ссылки, поиск и совместимые фильтры.
- Месяц с названиями событий, компактная неделя, почасовой день с параллельными событиями; три вкладки; обе темы и системная тема.
- IANA timezone, DST, отдельные даты «Весь день», повторения RRULE, исключения, изменения одного/последующих/всей серии.
- Персональные интервалы напоминаний, фоновая очередь в SQLite, сообщения на языке и в зоне получателя, отслеживание возможности доставки.
- Корзина на 30 дней, восстановление и досрочное окончательное удаление, включая отдельные экземпляры серии.
- ICS с VTIMEZONE и исключениями; подписанные Ed25519 ZIP, сравнение полей и ручной выбор восстановления.
- Полное удаление по согласию двоих, закрытый экран на 30 дней, отмена любым; восстановление после полного удаления только исходной парой и с двумя согласиями. После него каждый отдельно включает свои напоминания.

## Посмотреть на Windows

Установить Python **3.12 или новее**, скачать проект и дважды нажать **`start-demo.bat`**. Он создаст отдельную тестовую базу и откроет календарь в браузере. Пользователи 1 и 2 — тестовая пара, 3 — посторонний для проверки доступа. Это локальный демонстрационный режим; не публикуйте его в интернете.

Деморежим на macOS/Linux или для разработчика:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export DEMO_MODE=true
python -m scripts.demo_seed
python -m app
```

Открыть `http://127.0.0.1:8000`. В обычном режиме вход с тестовыми идентификаторами полностью отключён.

## Подключить настоящего Telegram-бота

1. Создать бота в [@BotFather](https://t.me/BotFather) через `/newbot`. Токен в GitHub не добавлять.
2. Разместить этот проект на сервере с HTTPS и постоянным диском. Ниже описан Railway.
3. В секретах сервиса заполнить `BOT_TOKEN`, `BOT_USERNAME` без `@`, `PUBLIC_URL` без завершающего `/`, `SESSION_SECRET`, `WEBHOOK_SECRET`. Два последних значения — разные случайные строки от 32 символов. Для их генерации предусмотрен `python -m scripts.create_secrets`.
4. Выставить `DEMO_MODE=false`. Для production приложение откажется стартовать без нужных секретов и HTTPS URL.
5. Выполнить **на сервере** `python -m scripts.setup_bot`: скрипт настроит защищённый webhook, команды и кнопку меню. Токен в вывод не попадает.
6. В BotFather: `/mybots` → выбрать бота → **Bot Settings → Configure Mini App → Enable Mini App**; установить тот же `PUBLIC_URL` как URL основной Mini App. Это нужно для ссылок `?startapp=join_…`.
7. Оба участника открывают чат и нажимают **Start / Запустить**. Первый создаёт календарь, в настройках формирует приглашение и отправляет второму. Второй открывает приглашение в Telegram.

## Размещение на Railway

1. **New Project → Deploy from GitHub repo** → выбрать репозиторий этого проекта. Dockerfile и `railway.json` находятся в корне.
2. Добавить сервису **Volume**, путь монтирования **`/data`**. До запуска убедиться, что диск подключён.
3. Установить переменные из `.env.example` в разделе **Variables**. Секреты задавать там, не в файлах репозитория.
4. Включить публичный HTTPS-домен сервиса и вписать его в `PUBLIC_URL`, затем применить изменения.
5. Оставить **одну реплику**, один процесс приложения. SQLite и встроенная очередь рассчитаны на этот режим.
6. В консоли сервиса выполнить `python -m scripts.setup_bot` и завершить настройки BotFather из предыдущего раздела.
7. Проверить `/health` и пройти сценарии [docs/RELEASE_CHECKLIST.md](docs/RELEASE_CHECKLIST.md).

Сервер и фоновые задачи должны работать постоянно: не включать засыпание сервиса. `/data` содержит базу **и ключ подписи архивов**. При потере диска без резервной копии пропадут данные; при потере ключей/реестра старые ZIP могут перестать проверяться. Политика ключей описана в [docs/OPERATIONS.md](docs/OPERATIONS.md).

Docker Compose для своего сервера:

```bash
cp .env.example .env
# Заполнить .env и обеспечить HTTPS reverse proxy.
docker compose up --build -d
docker compose exec calendar python -m scripts.setup_bot
```

## Проверки

```bash
pip install -r requirements-dev.txt
python -m pytest -q
python -m compileall -q app scripts
node --check web/app.js
```

CI повторяет эти проверки. Тесты не используют настоящие Telegram-сообщения, внешние календари и реальные пользовательские данные.

## Структура

| Путь | Назначение |
| --- | --- |
| `app/main.py` | HTTP API, авторизация, защита запросов, раздача Mini App |
| `app/service.py` | Права участников, календарь, события, корзина и жизненный цикл |
| `app/recurrence.py` | IANA timezone, DST, RRULE и развёртка экземпляров |
| `app/bot.py` | Telegram Bot API, webhook и постоянная очередь напоминаний |
| `app/backup.py` | Ed25519 ZIP, выборочное/полное восстановление, ICS |
| `app/sync_policy.py` | Протестированные правила будущих внешних интеграций; адаптеров пока нет |
| `web/` | Mini App без сборщика и сторонних frontend-зависимостей |
| `tests/` | Прикладные проверки прав, дат, очереди и восстановления |
| `docs/Our_Calendar_TZ.docx` | Исходное согласованное ТЗ без изменений |
| `docs/SPECIFICATION.ru.txt` | Текстовая копия ТЗ для поиска и ревью |

Официальные источники, сверенные при разработке: [Telegram Mini Apps](https://core.telegram.org/bots/webapps), [Bot API](https://core.telegram.org/bots/api), [Google incremental sync](https://developers.google.com/workspace/calendar/api/guides/sync), [Apple third-party access](https://support.apple.com/en-us/121539), [Railway Dockerfiles](https://docs.railway.com/builds/dockerfiles), [Railway Volumes](https://docs.railway.com/volumes).
