# Our Calendar

Приватный общий календарь для неизменяемой пары Telegram-аккаунтов. Telegram Mini App, бот, сервер и постоянное хранилище находятся в одном проекте.

**Версия 0.7.2 — рабочее ядро с тремя вариантами недели: прежний список дня, таймлайн на 3 дня и таймлайн на 7 дней. Полный объём ТЗ ещё не завершён.** Сервис и бот @ourcalendar_bot размещены на Railway. Финальная приёмка на двух настоящих аккаунтах и устройствах остаётся отдельной проверкой. Google/iCloud ещё не подключены к пользовательскому интерфейсу. Автоматический перевод RU/EN работает через отдельный приватный сервис LibreTranslate в Railway. Полная таблица готовности: [docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md).

## Что уже реализовано

- Серверная проверка подписи Telegram `initData`, срока действия и полномочий на каждое действие.
- Создание календаря, одноразовая отзываемая ссылка, атомарное присоединение первого второго участника; запрет третьего и замены пары.
- Выход с сохранением событий и возвращение только того же Telegram-аккаунта.
- Фоновый перевод событий и категорий через LibreTranslate с защитой ручных версий, повторными попытками и проверкой конкурентных правок.
- Создание и редактирование событий, RU/EN версии текста, категории/цвета, принадлежность, статусы, место, ссылки, поиск и совместимые фильтры.
- Месяц с названиями событий, компактная неделя, почасовой день с параллельными событиями; три вкладки; обе темы и системная тема.
- IANA timezone, DST, отдельные даты «Весь день», повторения RRULE, исключения, изменения одного/последующих/всей серии.
- Персональные интервалы напоминаний, фоновая очередь в SQLite, сообщения на языке и в зоне получателя, отслеживание возможности доставки.
- Корзина на 30 дней, восстановление и досрочное окончательное удаление, включая отдельные экземпляры серии.
- ICS с VTIMEZONE и исключениями; подписанные Ed25519 ZIP, сравнение полей, исключений серий и собственных настроек. Применение требует действительного одноразового серверного предпросмотра.
- Полное удаление по согласию двоих, закрытый экран на 30 дней, отмена любым; восстановление после полного удаления только исходной парой и с двумя согласиями. После него каждый отдельно включает свои напоминания.

## Посмотреть на Windows

Установить Python **3.12 или новее**, скачать проект и дважды нажать **`start-demo.bat`**. Он создаст отдельную тестовую базу и откроет календарь в браузере. Пользователи 1 и 2 — тестовая пара, 3 — посторонний для проверки доступа. Это локальный демонстрационный режим; не публикуйте его в интернете.

Деморежим на macOS/Linux или для разработчика:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export DEMO_MODE=true
python -m scripts.demo_seed
python -m app
```

Открыть `http://127.0.0.1:8000`. В обычном режиме вход с тестовыми идентификаторами полностью отключён.

## Подключить настоящего Telegram-бота

1. Создать бота в [@BotFather](https://t.me/BotFather) через `/newbot`. Токен в GitHub не добавлять.
2. Разместить этот проект на сервере с HTTPS и постоянным диском. Ниже описан Railway.
3. В секретах сервиса заполнить `BOT_TOKEN`, `BOT_USERNAME` без `@`, `PUBLIC_URL` без завершающего `/`, `SESSION_SECRET`, `WEBHOOK_SECRET`. Два последних значения — разные случайные строки от 32 символов. Для их генерации предусмотрен `python -m scripts.create_secrets`.
4. Выставить `DEMO_MODE=false`. Для production приложение откажется стартовать без нужных секретов и HTTPS URL.
5. При `AUTO_SETUP_BOT=true` сервер сам сверит имя бота через getMe и настроит защищённый webhook, команды и кнопку меню. При несовпадении имени webhook не меняется. Для ручной настройки остаётся `python -m scripts.setup_bot`. Токен в вывод не попадает.
6. В BotFather: `/mybots` → выбрать бота → **Bot Settings → Configure Mini App → Enable Mini App**; установить тот же `PUBLIC_URL` как URL основной Mini App. Это нужно для ссылок `?startapp=join_…`.
7. Оба участника открывают чат и нажимают **Start / Запустить**. Первый создаёт календарь, в настройках формирует приглашение и отправляет второму. Второй открывает приглашение в Telegram.

## Размещение на Railway

1. **New Project → Deploy from GitHub repo** → выбрать репозиторий этого проекта. Dockerfile находится в корне. Новый сервис использует настройки Railway, а не устаревший railway.json; точные параметры перечислены в docs/RAILWAY_DEPLOYMENT.md.
2. Добавить сервису **Volume**, путь монтирования **`/data`**. До запуска убедиться, что диск подключён.
3. Установить переменные из `.env.example` в разделе **Variables**. Секреты задавать там, не в файлах репозитория.
4. Включить публичный HTTPS-домен сервиса и вписать его в `PUBLIC_URL`, затем применить изменения.
5. Оставить **одну реплику**, один процесс приложения. SQLite и встроенная очередь рассчитаны на этот режим.
6. После добавления BOT_TOKEN и BOT_USERNAME дождаться автоматической регистрации webhook и завершить настройки BotFather из предыдущего раздела.
7. Проверить `/health` и пройти сценарии [docs/RELEASE_CHECKLIST.md](docs/RELEASE_CHECKLIST.md).

Сервер и фоновые задачи должны работать постоянно: не включать засыпание сервиса. `/data` содержит базу **и ключ подписи архивов**. При потере диска без резервной копии пропадут данные; при потере ключей/реестра старые ZIP могут перестать проверяться. Политика ключей описана в [docs/OPERATIONS.md](docs/OPERATIONS.md).

Docker Compose для своего сервера:

```bash
cp .env.example .env
# Заполнить .env и обеспечить HTTPS reverse proxy.
docker compose up --build -d
docker compose exec calendar python -m scripts.setup_bot
```

## Подключить автоматический перевод

В переменных сервиса указать `TRANSLATION_URL` — базовый HTTPS-адрес выбранного LibreTranslate без `/translate` либо адрес приватного сервиса Railway. При необходимости добавить `TRANSLATION_API_KEY`. Можно использовать собственный экземпляр сервиса; текст событий передаётся только настроенному оператором адресу. После изменения конфигурации перезапустить сервер.

Новые события/категории и изменения оригинала ставятся в фоновую очередь. Ручные версии защищены. В карточке события доступны «Перевести заново» и отдельная подтверждаемая замена ручных версий. При недоступности сервиса оригинал сохраняется, очередь повторяет попытку. После первого подключения автоматически ставятся в очередь и ранее созданные записи. `/health` показывает результат живой проверки обоих направлений на синтетическом тексте; ошибки не содержат текстов календаря. После четырёх ошибок повторные попытки продолжаются с увеличенным интервалом.

## Структура

| Путь | Назначение |
| --- | --- |
| `app/main.py` | HTTP API, авторизация, защита запросов, раздача Mini App |
| `app/service.py` | Права участников, календарь, события, корзина и жизненный цикл |
| `app/recurrence.py` | IANA timezone, DST, RRULE и развёртка экземпляров |
| `app/bot.py` | Telegram Bot API, webhook и независимые циклы напоминаний/перевода/копий |
| `app/backup.py` | Ed25519 ZIP, выборочное/полное восстановление, ICS |
| `app/translation.py` | Очередь LibreTranslate, защита ручного текста и проверка версий |
| `app/providers/` | Пилотные read-only адаптеры Google/iCloud, HTTPS transport и credential vault |
| `app/sync_policy.py` | Протестированные правила будущих внешних интеграций; адаптеров пока нет |
| `web/` | Mini App без сборщика и сторонних frontend-зависимостей |
| `tests/` | Прикладные проверки прав, дат, очереди и восстановления |
| `docs/Our_Calendar_TZ.docx` | Исходное согласованное ТЗ без изменений |
| `docs/SPECIFICATION.ru.txt` | Текстовая копия ТЗ для поиска и ревью |

Официальные источники, сверенные при разработке: [Telegram Mini Apps](https://core.telegram.org/bots/webapps), [Bot API](https://core.telegram.org/bots/api), [Google incremental sync](https://developers.google.com/workspace/calendar/api/guides/sync), [Apple third-party access](https://support.apple.com/en-us/121539), [Railway Dockerfiles](https://docs.railway.com/builds/dockerfiles), [Railway Volumes](https://docs.railway.com/volumes).

Развёрнутый движок: отдельный `calendar-translate`, образ `libretranslate/libretranslate:v1.9.5`, только `en,ru`, одна реплика в EU, лимит 1 GB RAM / 1 CPU. Публичного домена нет; приложение обращается к `http://calendar-translate.railway.internal:5000`. Этот сервис расходует оплачиваемые ресурсы Railway. Модели загружаются при первом старте контейнера; база календаря и ключи остаются на прежнем диске приложения.

## Изменения 0.3.0

Поиск учитывает изменённые экземпляры и их эффективные статусы, категории и принадлежность. В карточке серии можно выбрать другой месяц/экземпляр. Повторения настраиваются обычными полями без ручного RRULE; особые существующие правила сохраняются без потерь. Исправлены сохранение напоминаний партнёра, переход после разделения серии, перевод исключений, пустые переводы категорий и восстановление состояния корзины из ZIP.

Служебные копии ежедневно шифруются до отправки в отдельный приватный bucket Railway ams и проходят пробное offline-восстановление. Хранение — 7 дней. Ключ расшифровки находится вне рабочего volume. Отдельный зашифрованный журнал удалений обязателен при аварийном восстановлении: старая копия не возвращает окончательно удалённый календарь. Настройки показывают последнее состояние. Внешний monitor GitHub Actions проверяет работоспособность каждые 15 минут; расписание может задерживаться.

Подробности: [эксплуатация и аварийное восстановление](docs/OPERATIONS.md), [приёмка](docs/RELEASE_CHECKLIST.md), [хранение данных](docs/PRIVACY.md), [результаты проверки](docs/QA.md). Секреты и реальные данные не коммитятся.

## Изменения 0.3.1

Недельный заголовок показывает номер недели месяца выбранной даты и полный интервал понедельник–воскресенье с годом. Первая неполная неделя тоже считается; на границе месяцев номер относится к месяцу выбранной даты. Короткий горизонтальный свайп листает месяц/неделю/день, длинный влево переключает Месяц → Неделя → День, вправо — обратно, сохраняя дату. На крайних режимах длинный жест ничего не перелистывает. Подсказка показывает действие до отпускания пальца. Вертикальная прокрутка, масштабирование двумя пальцами и обычные нажатия сохранены. Месячные стрелки и свайпы сохраняют число, ограничивая его последним днём короткого месяца.

## Изменения 0.3.2

Календарь двигается вслед за пальцем, соседний период появляется с края. Незавершённый или отменённый свайп мягко возвращается назад. Смена месяца/недели/дня сопровождается сворачиванием и раскрытием содержимого; завершение длится 280 мс без пружинящего отскока. Соседние периоды заранее подгружаются в ограниченный кеш текущей сессии. Telegram даёт лёгкий тактильный отклик при достижении порога смены вида, если он поддерживается устройством. Настройка «Уменьшение движения» отключает перемещение и масштабирование.

## Изменения 0.4.0

День открывается первым. В настройках появились формат дня, непрерывный/постраничный месяц и длительность новых событий. Время формы и таймлайн учитывают текущую зону профиля; «Сегодня» возвращает к текущему дню. Добавлены недельные индикаторы категорий, принадлежность в таймлайне, создание долгим нажатием и перенос времени перетаскиванием. Новые уведомления открывают конкретное событие/экземпляр. Переходы стали плавнее, доступность reduced motion сохранена.

## Изменения 0.5.0

Нижняя панель по умолчанию: День → Месяц → Настройки. В Настройки → Touch Bar можно включить день, неделю, месяц, категории и менять порядок перетаскиванием либо стрелками; Настройки всегда последние и не отключаются. Конфигурация личная, входит в ZIP. Категории также доступны из настроек. Верхний переключатель видов убран; свайпы продолжают работать.

«Сегодня» находится слева от «+» и сохраняет текущий вид. В сегодняшнем таймлайне повторное нажатие возвращает к текущему времени. Прокручиваемый месяц — единая сетка непрерывных недель: две строки в видимой области, без пустых ячеек и повторяющихся дат между месяцами. Дни имеют общий фон, разделители только горизонтальные между неделями. Сохранены события, категории, долгое нажатие, подгрузка и ограничение семью месяцами.

## Изменения 0.5.1

Область вокруг «Сегодня» и «+» прозрачная во всех видах календаря: контент продолжается под кнопками, касания в промежутках доходят до календаря. Кнопки имеют отдельные контуры, последний контент доступен прокруткой выше кнопок.

Длинный свайп переходит к соседнему пункту в личном порядке Touch Bar, включая категории и настройки, пропуская скрытые виды. Влево — следующий пункт, вправо — предыдущий; на краях перехода нет. Короткий свайп по-прежнему листает даты только внутри календаря. Поиск, формы, поля настроек, диалоги и перетаскивание событий не перехватываются.
